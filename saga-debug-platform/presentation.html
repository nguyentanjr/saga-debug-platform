1. Bài toán đặt ra

Thực trạng

  • Giao dịch phân tán (Saga) qua 3-5 microservices — khó theo dõi khi lỗi
  • Debug thủ công: đọc log từng service, trung bình 30-60 phút/sự cố
  • Không có cơ chế phát hiện saga bị kẹt (stuck) — chỉ biết khi khách hàng phản ánh
  • Không liên kết được saga ID ↔ distributed trace (Jaeger)
  • Khi compensation thất bại → tiền bị trừ mà không hoàn → rủi ro tài chính

Mục tiêu

  • Giảm thời gian phát hiện sự cố từ 30 phút → < 2 phút
  • Tự động correlate tất cả event thuộc cùng 1 saga
  • Phân tích nguyên nhân gốc (RCA) tự động với severity + suggestions
  • Tích hợp distributed tracing (OpenTelemetry + Jaeger)
  • Dashboard giám sát real-time

3. Saga Flow — Happy Path & Compensation

✅ Happy Path (3 events)

ORDER_CREATED→ PAYMENT_COMPLETED→ INVENTORY_RESERVED

Status: STARTED → IN_PROGRESS → COMPLETED

RCA: HEALTHY Severity: NONE

🔄 Compensation Flow (5 events)

ORDER_CREATED→ PAYMENT_COMPLETED→ INVENTORY_FAILED→ REFUND_PAYMENT→ PAYMENT_REFUNDED

Status: ... → COMPENSATING → COMPENSATED

RCA: COMPENSATION_RECOVERED Severity: LOW

Recovery-Aware Analysis

STUCK → Recovered
STUCK_SAGA phát hiện → saga tự complete
→ RECOVERED_FROM_STUCK

Missing → Late
MISSING_COMPLETION → saga complete muộn
→ LATE_COMPLETION

Completed + anomaly
OUT_OF_ORDER + saga COMPLETED
→ COMPLETED_WITH_ANOMALY

5. Anomaly Detection Engine

detectOutOfOrder

Sort events by receivedAt (arrival order), kiểm tra timestamp (creation order) có monotonically increasing không. Clock skew tolerance: 2s.

detectStuckSagas (@Scheduled 30s)

Scan tất cả saga non-terminal. Lấy event cuối cùng, so sánh với timeout từ WorkflowSpec YAML (default 60s). Tạo anomaly nếu quá hạn.

detectMissingCompletion

Kiểm tra: có PAYMENT_COMPLETED nhưng không có INVENTORY event sau 30s → step bị thiếu completion.

detectInvalidTransition

Validate state transitions dựa trên WorkflowSpec YAML. VD: CREATE_ORDER → PROCESS_PAYMENT ✅, CREATE_ORDER → RESERVE_INVENTORY ❌

Workflow Spec (YAML-driven)

workflow:
  name: ORDER_SAGA
  steps:
    - id: CREATE_ORDER      | timeout: 30s
    - id: PROCESS_PAYMENT   | timeout: 45s | compensation: REFUND_PAYMENT
    - id: RESERVE_INVENTORY | timeout: 60s
  transitions:
    - from: CREATE_ORDER → to: PROCESS_PAYMENT (on: success)
    - from: PROCESS_PAYMENT → to: RESERVE_INVENTORY (on: success)
    - from: RESERVE_INVENTORY → to: REFUND_PAYMENT (on: failure)
