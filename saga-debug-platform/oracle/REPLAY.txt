SC06 / F4: paired replay before changing the rule
================================================

Requirements: Maven and Java for this repo; Python with
    python -m pip install -r oracle/requirements.txt

Run from the repository root, BEFORE F4:
    python oracle/replay_sc06.py --output results/sc06-before.json --verify-baseline results/evaluation_report_sc06_evidence_20260921.json
    python oracle/score.py results/sc06-before.json

AFTER F4 (same frozen input, NEW output path):
    python oracle/replay_sc06.py --output results/sc06-after.json
    python oracle/score.py results/sc06-after.json

Baseline verification requires the local original artifact. Replay and scoring do not:
oracle/sc06-observations.json contains the 15 stored observations and oracle-only source
state, with a SHA256 of the original artifact. No original diagnosis is copied as input.
Keep this fixture identical between builds. The scorer rejects different raw_events or
a modified fixture rather than silently reusing labels for another run with the same ID.

Scope: Sc06ReplayTest runs real CorrelationService, inline anomaly detectors, RcaService,
RuleRegistry and RcaSelector, using repository mocks. It starts at IngestedEvent (after
mapping), preserves payload, eventTime, receivedAt, transport identity and causal metadata,
and replays in recorded receivedAt order. Equal receivedAt values are rejected. Business
state and findings are recomputed; recorded anomalies/source_state are NEVER engine input.

Not covered: Kafka, SourceMapping ingestion, database transactions, live service state,
scheduled sweeps, retention, or scheduler timing. The decision point is immediately after
the final captured observation. SC06 is terminal and its recorded RETRY_BURST is inline;
this harness must NOT be reused to claim SC16/SC17 absence-detector fidelity.

Before-F4 verification compares status, anomaly types, primary roots, candidate order,
rule IDs, tiers, severity and anchors against the live artifact. The live artifact lacks
full explanation text, so matching those fields does NOT prove identical explanations.
The replay report includes full candidates to inspect explanations after F4.

Provenance: output contains input/resource/source SHA256s, Git revision, Java version,
detector settings, and whether sources changed during execution. Uncommitted files are
hashed too. Existing report/log files are not overwritten. Reports remain under ignored
results/; retain chosen results with the final experimental deliverables deliberately.

Oracle v2 corrects an unverified v1 bridge: TIMEOUT_RETRY_STORM requires timeout evidence
in R02, not just exhausted retries. STEP_FAILED_AFTER_RETRY_EXHAUSTION currently has no
verified platform label; this is visible, not replaced with an invented synonym.
No new independent review is claimed. Labels are retrospective, reviewed_by remains null.
Unknown platform labels are UNSCORED, excluded from score denominators, and oracle coverage
is printed. Historical reasoning defects in the YAML are NOT automatically assessments of
the replayed build. Review the newly emitted evidence before claiming F4 explanations fixed.

Checks:
    python -m unittest discover -s oracle -p "test_*.py" -v
    mvn -pl correlation-service -am test -Dtest=Sc06ReplayTest -Dsurefire.failIfNoSpecifiedTests=false
    mvn clean install
